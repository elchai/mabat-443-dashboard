# Security Findings — mabat-443-dashboard — 2026-05-11

Scope: single-page dashboard at `index.html` (~9715 lines) + public GeoJSON/JS data files. Firebase Auth (Google) + Firebase Realtime Database via REST. Public repo on GitHub Pages.

The two structural problems that account for most P0/P1 findings: (a) **all Firebase RTDB writes are sent as anonymous REST `PUT`/`DELETE` without an `?auth=<idToken>` parameter**, meaning real access control depends entirely on rules deployed in the Firebase console, which we cannot read but which the code assumes are permissive; and (b) **client-side approval gating is the only thing protecting the operations view** — every check happens in browser JS and is trivially bypassable.

## P1 — Significant

| # | file:line | Issue | Fix | Effort |
|---|---|---|---|---|
| 9 | index.html:8700-8705 | `escapeHtml` uses `div.textContent → div.innerHTML`. This encodes `<`, `>`, `&` but **NOT `"` or `'`**. Many call sites interpolate the result inside `"..."` or `'...'` attributes — see #10, #11, #12. | Replace with a proper escape that also encodes `"` → `&quot;` and `'` → `&#39;`, or use `setAttribute` instead of building attributes via template literals. | S |
| 10 | index.html:8041 | `onclick="openPublisherProfile('${escapeHtml(srcIdForProfile)}',event)"` — `srcIdForProfile` comes from item.source via RTDB. A field-report with `source: "x',alert(1),'"` (writable today, see #3) breaks the JS string and executes arbitrary code in the dashboard origin (operations view exposed). | Pass the id via `data-src-id` attribute + delegated handler, OR use `JSON.stringify(srcIdForProfile)` and the `"...".replace(/</g,'\\u003c')` pattern. | S |
| 11 | index.html:8043-8044, 8761-8765 | `<a href="${escapeHtml(tgLinkFull)}">` and `<img src="${escapeHtml(profile.photo)}">`. `escapeHtml` leaves `"` unescaped, so a value like `" onerror="alert(1)` breaks out of the attribute. Profile.photo is written from `handlePhotoUpload` (data: URL) and from RTDB — controllable per #3. Also: no protocol allowlist, so `javascript:` URLs in `tgLinkFull`/`sourceUrl` go through (line 8044). | Escape `"`/`'`, validate URL protocol (`/^(https?:|t\.me|\/)/`), reject `javascript:`/`data:` for `href`. | S |
| 12 | index.html:5441, 5452, 5489 | Video modal and Mapillary modal interpolate `${url}` and `${imageId}` **directly into `href=""` and `src=""` with no escape at all**. URL originates from RTDB `item.videoUrl`/Mapillary image id. Trivial DOM XSS if the value is malicious. | Use `setAttribute('href', url)` after a protocol-allowlist check. Same for `src`. | S |
| 13 | index.html:1-15 | No CSP, no `X-Frame-Options`, no `Referrer-Policy`, no SRI on the three external scripts (Firebase 10.7.1 from gstatic) or Leaflet/etc. A compromised CDN or MITM (GitHub Pages serves HTTPS, but the dashboard pulls many third-party origins) executes in your origin. | Add `<meta http-equiv="Content-Security-Policy" content="default-src 'self' https://*.gstatic.com https://*.firebaseio.com https://*.firebasedatabase.app https://router.project-osrm.org https://overpass-api.de https://graph.mapillary.com https://*.openstreetmap.org; script-src 'self' 'unsafe-inline' https://www.gstatic.com; ...">` and add `integrity=` + `crossorigin="anonymous"` to the Firebase script tags. | M |
| 14 | index.html:9513-9515 | `_emailKey` strips `.`, `#`, `$`, `[`, `]`, `/` to `_`. Two distinct Google emails can collide on the same key (e.g., `a.b@x.com` and `a_b@x.com` both → `a_b@x_com`). One approved user lets a different impersonator inherit their `user-plans/` namespace. | Use a non-lossy encoding (base64url of the email, or Firebase Auth UID which is exactly what RTDB rules can match on: `auth.uid`). | S |
| 15 | index.html:9543-9545 | `signOut()` removes Firebase auth but does NOT clear `arrestState`, the saved-plans DOM list, or `sessionStorage` (`mabat443-arrest-session-v1`). Anyone on the shared workstation after sign-out can still read the last user's plan from RAM/UI and from sessionStorage until tab close. | On signOut: `arrestClear(true); sessionStorage.removeItem(ARREST_SESSION_KEY); document.getElementById('arrestSavedList').innerHTML = '';` and force-redirect to dashboard view. | S |

| # | file:line | Issue | Fix | Effort |
|---|---|---|---|---|
| 16 | index.html:4807, 4810 | `reportId = 'field_' + Date.now()`. Two clicks within the same millisecond, or two concurrent users, collide and overwrite each other's field reports silently. Combined with #3 (open write), one bad actor can intentionally overwrite real reports by submitting one with the same `field_<ts>` id. | Use `crypto.randomUUID()` or Firebase's `push()` key, and verify uniqueness with a transaction. | S |
| 17 | index.html:4660-4671, 4807-4827 | Field reports accept arbitrary HTML/text from anonymous users, write to RTDB, and re-render via `escapeHtml(item.title)`. However, if anyone with RTDB write (per #3) sets `source` directly, it flows into `onclick="openPublisherProfile('${escapeHtml(source)}',event)"` per #10. | Server-side validation of `auto-news/*` entries (length caps, allowed source list, schema). Until then, treat all RTDB read fields as untrusted in renderers. | M |
| 18 | index.html:8042 | Manual escape `escapeHtml(item.videoUrl).replace(/'/g,'\\\'')`. Inside an onclick that's already inside `"..."`, this leaves the value vulnerable to `"` injection. Inconsistent with the rest of the file. | Use a unified safe-attr helper or data-* + delegation. | S |
| 19 | index.html:9709 | `Auth.init()` calls `firebase.initializeApp(FIREBASE_AUTH_CONFIG)` unconditionally. If a service worker or hot-reload re-enters init, throws `'Firebase: Firebase App named '[DEFAULT]' already exists'`. Caught only by outer try, leaving Auth permanently unready. | Wrap with `if (!firebase.apps.length) firebase.initializeApp(...)`. | S |
| 20 | index.html:8859-8868 | `handlePhotoUpload` reads file as data URL and writes the raw `e.target.result` into `pe_photo` value, which is then PUT to `publisher-profiles/<id>.json` and later interpolated into `<img src="${escapeHtml(profile.photo)}">`. No MIME validation — a `text/html` "photo" served from a data URL can still navigate or pop-up on click in some browsers when rendered in attributes that don't enforce the image MIME. | Verify `file.type.startsWith('image/')` before reading, and on render check `profile.photo.startsWith('data:image/') || profile.photo.startsWith('https://')`. | S |

Closure data is OCHA-public, but the **combination** with operations planning + arrest target placement reveals which fence segments / road gates the unit cares about. | Move geo data behind an authenticated proxy (Cloud Function returns geo only to approved users) and remove from the repo + GitHub Pages. ## Positive findings (what's done well)

- `escapeHtml` is consistently called on user-controlled strings flowing into `innerHTML` for the alert/feed/history renderers (titles, summaries, snippets, AI extract chips, matched keywords) — the residual XSS risk is from missing `"`/`'` escaping inside attributes, not from raw concatenation of fields like `item.title`.
- No `eval()`, no `new Function()`, no `document.write` anywhere in the file. Good baseline.
- No `dangerouslySetInnerHTML` (not React anyway, but no equivalent patterns).
- No `postMessage` listeners — no cross-window XSS surface.
- Sign-in uses Firebase popup (commit `67507cc`) instead of redirect, which is the correct choice on GitHub Pages (no 3rd-party cookie problem).
- Sensitive operational text (target name, plan name) is escaped before rendering in saved-plans list (`escapeHtml(p.targetName)` at line 7112).
- AbortSignal.timeout on all external `fetch()` calls (5s–30s) — prevents hung tabs.
- `closures` and `fence` data shipped as inline static files with localStorage cache fallback, reducing live external calls.
- File-size cap on photo upload (`file.size > 500000` at line 8862).
- 50-plan cap on `UserPlans.add` prevents unbounded growth.
- `popup-closed-by-user` / `popup-blocked` handled distinctly in `signIn` (line 9535-9539) — good UX-aware error handling.
